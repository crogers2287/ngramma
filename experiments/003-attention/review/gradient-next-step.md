# Next gradient gate after exact baseline forward agreement

The reported exact 48-layer/logit result qualifies one forward configuration and sequence. It does not provide a backward implementation, demonstrate useful row-update directions, or admit training. This note proposes an experiment; no gradients or perturbed-model results were measured here.

## What “the derivative” must refer to

There are three different objects:

1. **A smooth reference computation.** Dequantize fixed weights once, use ordinary floating-point linear operations, and omit activation rounding. Away from top-k changes, clamp/sign boundaries, and other nonsmooth points, autograd can differentiate its real-arithmetic interpretation. Agreement with its own finite differences qualifies that reference's derivative only. It is not the deployment function qualified by the native forward work.
2. **An explicit-quantization mathematical model.** Keep activation quantization in the forward definition. Fixed-scale rounding is piecewise constant, has derivative zero inside a bin, and is discontinuous at thresholds. Adaptive block scaling changes this conclusion: integer codes may stay fixed while the scale changes. The derivative can then be nonzero through the scale, or undefined when the maximizing component changes. “Same integer codes” is not enough to call a quantizer constant.
3. **The actual finite-precision serving program.** Its inputs, scales, reductions, and outputs are represented as discrete floats. Directional finite differences measure responses over a specified representable perturbation size; an infinitesimal mathematical derivative is not automatically the useful notion. An all-zero difference can mean an unchanged quantized representation or simply insufficient numerical resolution. A threshold-spanning secant is a deployment sensitivity, not an exact local derivative.

The source makes adaptive scaling concrete. `ggml/src/ggml-quants.c:278–301` describes Q8_0's max-derived scale, stored as FP16, and rounded integer codes. `:2770–2807` describes Q8_K's signed max-derived scale stored as FP32, integer codes, and block sums. Storage is explicit in `ggml/src/ggml-common.h:251–256,371–376`. These reference implementations establish representation semantics; instrumentation must use the actual selected CPU quantizer, including any repacked input conversion, rather than assuming reference and dispatched rounding are identical.

For an idealized Q8_K block with fixed maximum index and codes, decoded values are `scale(x) * codes`; variation through scale remains. For Q8_0, an unchanged encoded FP16 scale and unchanged codes make the decoded block exactly constant. To establish a deployed plateau, compare **complete encoded activation bytes, including scale and auxiliary sums**, not only code indices or quantizer type.

It is also incorrect to assume the entire model is locally constant merely because it contains quantized matmuls. Unquantized operations, adaptive scales, and residual routes may transmit variation around a quantizer. Selected memory rows first enter PLE through its key and value projections (`src/models/qwen4exp.cpp:1657–1658`); the memory vector is not added directly to the residual. Key/query normalization and gating, value gating, dilated convolution, and the residual sum follow (`:1660–1689,1725–1740`; replica `vendor/engraft/replica/layers.py:476–503`). Consequently, if both PLE projections truly return identical outputs at every edited-row occurrence, with the same prior hidden states/history, the downstream deterministic computation must remain identical. Whether those projections quantize activations, and in which formats, must be read from their actual weight/buffer traits; it is not implied by the memory table's storage type.

## Where a backward pass becomes a surrogate

The current native bridge has no backward implementation. `src/ngramma_runtime/_sequence.py:28–30` refuses gradient-enabled full forwards. Adding a custom backward that returns the usual dense linear gradient across native activation rounding would be a **surrogate**, even if its forward is bit-exact.

The archived experimental estimator demonstrates that choice explicitly: `reference/flash_memory/experimental_gradient.py:13–15` returns the incoming gradient unchanged through `_StraightThrough`. This is the identity straight-through estimator, not the derivative of quantization. Its remaining float matrix products also predate the now-qualified native forward dispatch, so its forward cannot be assumed qualified by the new result.

Similarly, using a detached/native forward value plus a smooth Torch expression solely for gradient flow changes the backward definition. Replacing a native FMA/reduction with mathematically equivalent smooth backward operations is a conventional numerical derivative approximation; replacing a discontinuous quantizer with identity is a more substantive modeling choice. Both must be named, tested, and scoped. Holding selected experts or sparse attention choices fixed additionally gives a conditional derivative, not the complete response to routing changes.

## One bounded, falsifiable experiment: a single-row directional response curve

Use the already qualified public ten-token baseline, one existing row actually accessed by it, and one predeclared direction in that row's 160 coordinates. Share the row perturbation at every occurrence, exactly as serving does. Normalize direction magnitude by the original row RMS. Use a fixed last-position logit margin between two predeclared token IDs as the scalar response; choosing IDs before perturbation avoids changing the objective to fit results. No teacher, optimization loop, or training examples are needed.

1. **Fix the forward condition and verify zero edit.** Pin checkpoint, overlay semantics, baseline row bytes, input tokens, native library/engine identities, cache settings, and direction. A fresh zero-edit export must reproduce the baseline exactly. Capture actual PLE key/value projection weight types, buffer types, quantized activation bytes, and outputs at all occurrences. The sparse attention selection must run normally for perturbed engine forwards; the current baseline-support-verified dense diagnostic cannot establish sparse selection invariance after an edit.
2. **Qualify a named smooth control independently.** On the same PLE input fixture, define an explicit smooth reference scalar (for example, a fixed linear readout of PLE output), freeze routing where relevant, and compare its autograd directional derivative to central differences of that *same smooth function*. Use a predeclared epsilon ladder, such as row-normalized `2^-16, 2^-14, 2^-12, 2^-10, 2^-8, 2^-6, 2^-4`. Report its convergence region and numerical noise floor. This is a local derivative plumbing check, not full-model or deployment-gradient admission.
3. **Measure the native PLE response over the identical ladder.** Evaluate plus/minus perturbations through the actual CPU PLE projections/subgraph. Record row changes after FP32 export, full activation-quantizer bytes, projection/output differences, and scalar secants. Mark unchanged-representation intervals, scale-only changes, code/scale threshold changes, and any clamp/sign crossings. This bounded subgraph survey chooses the steps for the full-engine check without repeatedly running the entire model at every epsilon.
4. **Check only three predeclared categories in the full serving engine.** If found, select the smallest plateau step, the first observed encoded-representation change, and the next larger ladder step. Evaluate plus/minus row overlays with fresh state and normal live routing, recording the fixed logit-margin secant and expert/QSA selections. If a category does not exist, report that fact instead of inventing a crossing. Six perturbed forwards at most, plus the zero control, suffice for this first discrimination experiment.
5. **Interpret by a falsifiable rule.** If the smooth derivative passes its own finite differences but native quantizer outputs and logits stay bit-identical at the plateau step, a nonzero STE prediction is demonstrably not the deployed local response there. If native output changes at a threshold, report finite-step sensitivity and whether the surrogate predicts its sign/magnitude; do not call that derivative convergence. If scales vary with stable codes, account for those variations before attributing disagreement to a threshold. If PLE outputs are identical yet final logits change under identical fresh state, reject the experiment as an isolation/state/control failure and investigate before considering training.

This experiment can separate broken gradient plumbing from a correct but deployment-mismatched surrogate. One row and direction cannot qualify a general optimizer, and a zero local deployment response does not show that useful finite row edits are impossible. A later surrogate-training proposal would need evidence that its recommended finite updates predict deployment changes across multiple independent directions, row occurrences, magnitudes, and preservation cases, with routing recomputed and an explicitly chosen update scale.
