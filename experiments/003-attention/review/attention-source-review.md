# Layer-3 full-attention source review

This is source inspection, not model execution or fixture attribution. The supplied prior result has layers 0–2 bit-identical and first disagreement at layer 3 (maximum 0.000202383, relative RMS 0.000560558). The native adapter currently covers weight matrix operations, elementwise functions, normalization, sums, convolution, and recurrent attention; full-attention RoPE and its two tensor contractions still use the replica implementation.

## Candidate differences in execution order

1. **First isolate RoPE after matching projections and normalization.** Replica `vendor/engraft/replica/layers.py:134–155` computes each inverse frequency independently with FP64 powers, positions, cosine, and sine, then casts trigonometric values to FP32. Engine `ggml/src/ggml-cpu/ops.cpp:6185` computes `theta_scale = powf(freq_base, -2.0f/n_dims)`, starts from FP32 positions, repeatedly multiplies theta by that FP32 factor (`:6033–6099`), and uses `cosf`/`sinf` (`:6013–6014`). Equal mathematical angles do not imply equal rounded angles. Rotation uses paired multiply/subtract and multiply/add (`:6104–6119`), potentially with compiled contraction. Plain-text equal position axes remove IMRoPE's sector-selection distinction but do not remove these numeric differences. Replica also does not represent all engine scaling parameters; capture actual `freq_scale`, `ext_factor`, `attn_factor`, correction parameters, mode, and original context before assuming their defaults.

2. **F32 cache does not guarantee F32 attention operands when flash attention is enabled.** `src/llama-graph.cpp:2568–2576` explicitly casts F32 K and V to F16 before `ggml_flash_attn_ext`, and sets its precision parameter to F32. This is a forward operand change relative to the replica's all-F32 dense attention. It applies only if this run selects flash attention. Inspect the captured graph opcode and operand types; do not infer it from cache flags alone. The fused CPU kernel has its own tiled/online reductions, so merely rounding K/V in Torch is not an exact-forward substitute.

3. **Without flash attention, QK and PV still need native batched graph operations.** Replica `layers.py:234–239` uses Torch einsum for QK and PV. These activation–activation batched operations are outside the registered weight `mm`/`mv` hook. Engine `src/llama-graph.cpp:2603–2655` builds `ggml_mul_mat(k,q)`, `ggml_soft_max_ext` with scale and mask, then `ggml_mul_mat(v,kq)`. Native unary softmax on an already scaled/masked short matrix is not evidence of equivalence to this complete graph. Carry the same mask, key-window length, physical layouts, head grouping, scale, and optional bias/sink parameters.

4. **QSA is computed even for a short sequence in this engine source.** Replica documentation says selection is skipped for T<=top_k, but `src/models/qwen4exp.cpp:1153–1167` calls `build_qsa_top_k` whenever indexer context and compression ratio are present; `:971–977` chooses width `min(n_kv, indexer_top_k + ratio - 1)`. Short-sequence dense equivalence is a statement about selected visible keys, not absence of an indexer graph. Capture selected IDs and masks to verify all causal real keys are retained. If all are retained, do not spend time matching indexer arithmetic before matching attention arithmetic.

5. **Cache window and scan/gather ordering are part of numerical parity.** Engine QSA chooses gather only when enabled, flash is active, and `4 * queries_per_stream * selected_width < n_kv` (`qwen4exp.cpp:1035–1041`); otherwise it scans the full cache window with an augmented mask. Gather places keys in selected-index order; scan keeps cache-cell order. The replica contracts only concatenated real tokens in sequence order. Masked padding and a changed key order can alter reduction grouping even if the mathematical distribution is unchanged. Verify actual `n_kv`, cell indices, original mask, QSA mask, and cache operand shapes/strides/types.

The query/gate interleaving, Q/K normalization placement, post-attention sigmoid gating, and grouped-query head convention appear structurally aligned in the inspected code. Engine MHA head broadcasting divides query-head index by the replication factor; replica `repeat_interleave` expresses that grouping. This is source consistency, not a numerical qualification. Existing f32-cache captures do not establish behavior with quantized-cache Hadamard rotations (`qwen4exp.cpp:994–1002`), so new native contracts should reject unsupported rotations or accept already rotated cache tensors explicitly.

## Specific capture request

Capture both occurrences where names repeat, preserving shape, stride, type, graph opcode, and ancestor weight-buffer type:

1. `hc_mixed-3` first occurrence; `Qcur_full-3`, `Qcur_reshaped-3`, `Qcur_normed-3`, raw `Kcur-3`, `Kcur_normed-3`, `Vcur-3`, `gate_reshaped-3`.
2. Post-RoPE `Qcur-3` and `Kcur-3`; full RoPE operator parameter bytes or decoded values and complete I32 position input.
3. Actual MHA q/k/v operands after permutation/cache access and any F16 cast, including shape/stride/type; original KQ mask, `indexer_top_k-3`, final QSA mask or `qsa_k_sel-3`, `qsa_v_sel-3`, `qsa_mask_sel-3` if gathering.
4. Nonflash: `kq-3`, `kq_soft_max-3`, `v_cont-3` where present, `kqv-3`. Flash: the `GGML_OP_FLASH_ATTN_EXT` result and all operand/op parameters; separate intermediate QK/softmax nodes may not exist.
5. `attn_pregate-3`, `gate_sigmoid-3`, `attn_gated-3`, `attn_output-3`, then final HC combine. This identifies where small differences are amplified by output-projection activation quantization.

For a first causal probe, substitute only exact post-normalization Q/K into native RoPE, then compare from exact post-RoPE q/k/v through the selected native attention path. Avoid simultaneously replacing every stage before locating the earliest nonexact output.

## Native operation contracts

**RoPE bridge:** contiguous CPU F32 input in Torch `[T,H,D]`, GGML dimensions `[D,H,T,1]`; I32 positions arranged as four consecutive length-T axes for IMRoPE; explicit `n_rot`, sections[4], rope mode, original context, frequency base/scale, extrapolation/attention factors and beta parameters. Call `ggml_rope_multi` and return the same shape. Preserve unrotated tail channels. Do not reproduce the engine's trig recurrence in Python when the native operator is available.

**Attention bridge:** accept exact engine operands and mask rather than reconstructing a model cache. For ordinary scan use q/k/v inputs representing `[Tq,Hq,D]`, `[Tk,Hkv,D]`, `[Tk,Hkv,Dv]` with explicit physical cache layout or a proven equivalent conversion; preserve Tk including masked cells. In the graph, permute to q `[D,Tq,Hq,streams]`, k `[D,Tk,Hkv,streams]`; prepare v layout according to the engine branch. Nonflash graph is native KQ matmul (F32 precision), `ggml_soft_max_ext(scale,mask,max_bias)`, and native V multiplication, followed by the same permutation/recombination. Flash graph is native `ggml_flash_attn_ext` with the exact K/V operand casts and mask type, precision, scale, softcap, and sink configuration. Preserve Tq batching and key order because kernel selection and reductions depend on them.

A bounded first contract can reject multiple streams, gather mode, nonzero ALiBi/softcap, sinks, and quantized operands until their fixtures are available. Such rejection must be explicit; it is preferable to silently treating a different attention path as equivalent. No backward path or training qualification follows from either bridge.
